# 开发记录

这份文档记录项目怎么来的、每个版本改了什么，以及踩过的坑。技术细节比 README 多一点。

## 一、由来：从一个只剩 exe 的现场把源码找回来

这个工具最初是给一个封闭内网的办公环境写的：坐席在电脑前查资料，但通话要走桌面话机，
需要一个"点一下就把电话打出去"的小程序。要求很硬：

- 单文件、离线、拷进 U 盘就能用（内网没有外网，装不了运行库）
- 中文界面和日志（现场没人看得懂英文报错）
- 不能依赖任何第三方库

第一版（v1.4）做完之后，代码被后续的"全功能改造"覆盖掉了，本机只剩下一个打包好的
`拨号.exe`。于是有了这段"从二进制还原源码"的经历。

### 还原方法

不能靠"看起来像"，得可复现。做法是：用还原出来的源码重新编译，和原始 exe 逐字节比。

| 比对项 | 结果 |
|---|---|
| 重新编译后的文件大小 | 133,938 字节，与原始 exe **完全相同** |
| 16 个 PE 节区（.text/.rdata/.data/.pdata/…） | **逐字节一致** |
| 261 个函数反汇编逐条指令（地址归一化后） | **261/261 一致** |
| PE 头差异 | 仅 `TimeDateStamp`（偏移 0x88，4 字节）与 `CheckSum`（0xD8，2 字节） |

那 6 个字节是链接时刻写进 PE 头的编译时间戳和校验和，**每次编译都会变**（连续编译两次也差这 6 字节），
与源码无关。所以结论是：这份源码就是当初编译出那个 exe 的源码。

> 这条"逐字节一致"只针对 v1.4 那一刻。后面加功能之后自然不再相同，
> 但 `验证还原.py` 校验的是"当前源码 ↔ 当前 exe"，随时可以复现。

### 为什么要提这件事

两个原因：一是证明当前代码不是"重写了一个差不多的"，而是原样恢复；
二是这套比对方法（忽略 PE 时间戳和校验和）在做二进制逆向、验证构建可复现性时挺好用。

## 二、版本记录

### v1.4 —— 纯拨号版

- 主叫：下拉框选分机（自动从 PBX 拉列表，上限 2000 个），也可手输；主叫记在 ini
- 被叫：历史列表（最近 12 个，去重），启动时不预填，避免误拨
- 按钮：拨号 / 挂机 / 诊断 / 刷新分机 / 复制日志
- 手写 MQTT 3.1.1：QoS0/1、keepalive 60s、clean session、断线自动重连
- 单文件静态链接，配置与日志自动生成在 exe 同目录

### v1.4.1 —— "自动接通"变成配置项

1. `Settings` 里加 `int autoanswer`，ini 新增 `autoanswer=1/0`；**没有这个键时按 1 处理**，
   老 ini 升级上来第一次启动就是勾上的
2. 启动按 ini 恢复勾选框；界面改动**立即写回 ini**
3. 拨号时读勾选框决定 `"autoanswer":"yes"/"no"`

顺带把界面文字从"自动应答"改成"自动接通"，与接口语义一致。

### v1.4.2 —— 界面精简 + 回车拨号 + 双击历史直拨

1. **回车拨号**：被叫框回车直接拨；主叫框回车时被叫有号码就拨、没号码就把焦点跳过去
2. **双击历史直拨**：被叫从 COMBOBOX 改成 `EDIT + 【▼】按钮 + 弹出 LISTBOX`，
   单击填入、双击直拨、Esc 关闭、失焦收起
3. **界面精简**：ini 新增 `show_diag`（默认 0），为 0 时不创建【诊断】【复制日志】两个按钮，
   【刷新分机】左移补位

### v1.4.3 —— 修两个问题（2026-10-30）

1. **历史号码单击/双击不生效** —— 最后改成"和主叫一样的普通下拉框"。
   中间试过两版自定义列表，都踩了坑（见踩坑第 2 条），结论是：**下拉框就用系统自带的**，
   选中即填入、回车即拨，稳定可靠，也不再需要自己管弹出/收起/重绘。
2. **【刷新分机】字体和别的按钮不一样**：`apply_font()` 之前只对"连接/断开/拨号/挂机"
   调过，右边这三个按钮（诊断/刷新分机/复制日志）漏了，于是退回系统默认字体。
   现在统一成同一个 `HFONT`，测试里直接用 `WM_GETFONT` 比对三个按钮的句柄是否相同。

测试 **72 项**：dial 9 + caller 14 + extlist 7 + ini 5 + diag 5 + autoanswer 12 + ui 20。
`e2e_ui` 覆盖：默认隐藏诊断按钮、ini 自动补写 `show_diag=0`、被叫下拉框条数与选中、
回车拨号、空被叫不拨号、三个按钮字体一致、`show_diag=1` 恢复按钮。

### v1.4.4 —— 日志自动滚到最新 + 日志区排版（2026-10-30）

1. **状态日志自动滚动**：原来一直往下加，超过一屏就只能看到开头。
   现在每写一条都会把视图滚到末尾。
   *踩坑*：`EM_SCROLLCARET` 在**只读、没有焦点**的多行编辑框里会把视图滚回顶部
   （光标停在 0），必须改用 `EM_LINESCROLL`，它自己会夹到末尾。
2. **"状态日志"标题和文本框打架**：分组框在 y=260、文本框在 y=272，只差 12px，
   标题文字压在框线上。现在分组框 252、文本框 280，标题下方留 27px，底部留 11px。

### v1.4.6 —— 主叫下拉框只显示已注册的分机（2026-10-31）

PBX 的 `extension_list` 会返回**所有配置过的**分机，但只有注册上的才能打电话。
接口本来就把状态放在 `status` 字段里：

| status | 含义 | 是否可用 |
|---|---|---|
| `Idle` / `InUse` / `Ringing` / `Busy` | 空闲 / 通话中 / 振铃 / 忙 | ✅ 可用 |
| `Unavailable` | 未注册 / 掉线 | ❌ 打不通 |

所以不用新接口，直接按 `status` 过滤即可。实现要点：

1. `ext_add()` 多收一个 `status` 参数，`Unavailable`（另外兼容 `Unregistered`/`Offline`/
   `Disabled`/`Unreachable`）的直接跳过，同时计数。
2. ini 新增 `only_registered`（默认 1）。改成 0 就退回"显示全部"。
3. **兜底**：如果整份列表都被标成 `Unavailable`（老固件不返回 `status`），
   自动退回显示全部并在日志里提示，免得一个分机都选不了。
4. 日志从"共 N 个分机"改成"已注册 N 个 / 共 M 个（未注册的 K 个已隐藏）"。

*踩坑*：兜底扫描的触发条件原本写成"加进下拉框的数量为 0"，而过滤时这个值天然就是 0，
于是会把整份 JSON 再扫一遍，总数直接翻倍（12 个分机报成 24 个）。
判断依据必须是"解析到几个对象"（`g_ext_total`），不能用"加进去几个"。

## 三、踩坑清单

写 Windows 原生 GUI + 手写 MQTT，坑基本都在"没人告诉你"的地方。

### 1. 直接给 COMBOBOX 装窗口过程，会让 `SetWindowTextW` 失效

为了拦回车，最直接的做法是给组合框 `SetWindowLongPtr(GWLP_WNDPROC)`。结果：主叫分机
再也回填不出来——`SetWindowTextW` 调用了，但文字就是不见。

**原因**：COMBOBOX 内部对自己的编辑子窗口有一套特殊处理，替换组合框自身的窗口过程会
干扰它转发 `WM_SETTEXT`。

**解法**：只钩**编辑子窗口**（`GetComboBoxInfo()` 拿 `hwndItem`），焦点本来就在它上面，
回车照样能拦到。

### 2. 弹出窗口（WS_POPUP）做控件，点击和通知都不可靠

最初把被叫历史做成了一个 `WS_POPUP` 的列表框（带 owner，浮在被叫框下方）。结果：
**能看到列表、能点中、`LB_GETCURSEL` 也变了，但父窗口收不到任何 `LBN_SELCHANGE` /
`LBN_DBLCLK`** —— 单击不填入、双击不拨号，只有回车能用（回车是我们自己在子类化里处理的）。

排查过程：日志里 `WM_LBUTTONDOWN` 到了、`GetWindowLong(GWL_STYLE)` 确认 `LBS_NOTIFY` 是置上的、
`GetParent()` 也确实返回主窗口，但主窗口的 `WM_COMMAND` 一条都没收到。

结论：**别拿 WS_POPUP 当控件用**，改用 `WS_CHILD` 的子窗口（平时隐藏，显示时
`SetWindowPos(HWND_TOP)` 浮到兄弟窗口之上）。子窗口的通知天然发到父窗口，`hMenu` 也能正常当控件 ID 用。

顺带记一个相关的坑：`WS_POPUP` 窗口的 `hMenu` 参数会被当成**菜单句柄**，传控件 ID 会直接创建失败
（`err=1401`，ERROR_INVALID_WINDOW_HANDLE，跟"句柄无效"八竿子打不着）。

**最终结论**：绕了两版（弹出窗口、隐藏子窗口）之后，还是回到**系统自带的 COMBOBOX**。
它没有单击/双击的花活，但"选中即填入 + 回车拨号"够用，而且零维护——
自己画的列表要处理弹出、收起、重绘、z 序、失焦，每一样都能出岔子。

做被叫历史弹出列表时：

```c
CreateWindowExW(WS_EX_TOOLWINDOW, L"LISTBOX", L"被叫历史",
                WS_POPUP | ..., 0, 0, 200, 200,
                hwnd, (HMENU)IDC_HISTLIST, hInst, NULL);   /* ← 失败 */
```

返回 NULL，`GetLastError()` 是 **1401**（ERROR_INVALID_WINDOW_HANDLE），跟"窗口句柄无效"
八竿子打不着，排查了很久。

**原因**：对 `WS_POPUP` 窗口，`hMenu` 参数不是控件 ID，而是**菜单句柄**。
传个 1019 进去，系统拿它当 HMENU 去校验，直接失败。

**解法**：传 `NULL`，窗口靠标题识别，通知照样通过 owner 回到父窗口。

### 3. 原生下拉框收不到双击

`CBN_DBLCLK` 只在 `CBS_SIMPLE` 样式下才会发。`CBS_DROPDOWN` 第一次点击就把列表收起来了，
第二次点击根本落不到列表上——所以"双击历史项拨号"用原生下拉框做不到，必须自己做弹出列表。

### 4. `WS_CLIPCHILDREN` / `WS_CLIPSIBLINGS` 用错会把界面画成一片空白

这两个样式是为了修"历史列表被按钮挡住"加的，结果把界面弄坏了两次，记下来：

**第一次：主窗口加 `WS_CLIPCHILDREN` → 三个分组框里一片白。**
`WS_CLIPCHILDREN` 让父窗口重画背景时跳过所有子窗口区域。而 `BS_GROUPBOX` 只画边框和标题，
**不填内部**——它的内部本来就靠父窗口刷背景。父窗口一跳过，分组框里就成了没画过的白色。

**第二次：给所有子控件加 `WS_CLIPSIBLINGS` → 按钮、输入框、下拉框、标签全看不见了。**
`WS_CLIPSIBLINGS` 的语义是"我画的时候，把重叠的兄弟窗口从我的更新区域里剪掉"。
而这个界面上**每个控件都和分组框重叠**（分组框铺满整个区域），于是每个控件的可绘制区域
都被剪没了，只剩分组框的边框和标题还看得见——**鼠标点上去还有反应，因为剪的只是绘制，不是命中测试**。

**最终做法：两个样式都不加**，保持最初的写法。分组框内部靠父窗口刷背景，子控件各自正常绘制。
（顺带说明：如果以后确实需要父子重叠，正确姿势是父窗口 `WS_CLIPCHILDREN` + 分组框自己
处理 `WM_ERASEBKGND` 填背景，而不是无脑给所有控件加 `WS_CLIPSIBLINGS`。）

### 5. 跨进程读控件文字要 `WM_GETTEXT`，不能用 `GetWindowTextW`

写端到端测试时：`GetWindowTextW` 从别的进程读控件，永远返回空串（它其实是发 `WM_GETTEXT`，
但对跨进程的隐式调用不生效）。要显式 `SendMessage(WM_GETTEXT)` 并自己准备缓冲区。

同理，往别的进程的下拉框里设值，`CB_SETCURSEL` 可靠，`SetWindowTextW` 不可靠。

### 6. 订阅通配主题可能被拒

有的 MQTT 服务器对 `device/<token>/#` 这种通配订阅有限制。程序的做法是：先试通配，
SUBACK 返回失败码就自动退回 `response` + `event` 两个精确主题。日志里能看到
"订阅被服务器拒绝，改用精确主题"。

### 7. QoS1 的 PUBACK 是最好的现场诊断工具

命令用 QoS1 发，日志里能看到服务器的 PUBACK。这样在现场就能区分两种"没反应"：
报文根本没被服务器接受（无 PUBACK），还是服务器收了但 PBX 没处理（有 PUBACK 无 response）。
`show_diag=1` 时的【诊断】按钮就是干这个的。

### 8. 高 DPI

界面坐标全部走 `SC()` 按 `GetDpiForWindow()` 缩放，字体按 DPI 重算，
不依赖 manifest 里的 dpiAware（老系统上不一定生效）。

## 四、测试策略

没有真机也能测：本地起一个 amqtt broker，再起一个 paho-mqtt 写的"假 PBX"
（订阅 `device/<token>/api/v1.0/command/#`，按文档格式回 response、推 event），
然后驱动真实 exe 跑完整链路。

UI 操作全部走 Win32 消息（`BM_CLICK`、`CB_SETCURSEL`、`WM_SETTEXT`、`WM_KEYDOWN`），
不依赖鼠标坐标和屏幕分辨率，所以能在无人值守的机器上跑。
