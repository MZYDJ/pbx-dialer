========================================================================
                         PBX 拨号器  使用说明
========================================================================

一、这是什么
------------------------------------------------------------------------
一个绿色小软件：在电脑上填写主叫分机、输入被叫号码，点一下【拨号】，
就能让 PBX（Smart PBX Manager）替你把电话打出去；点【挂机】挂断。
通过 PBX 的 MQTT 接口控制，不经过任何外部服务器。

单文件程序，免安装、免配置运行库，拷贝到 Windows 电脑双击即可用。


二、运行方法
------------------------------------------------------------------------
1. 把「拨号.exe」和本说明放到任意文件夹（例如 D:\拨号\）。
2. 双击「拨号.exe」即可打开界面。
   - 首次运行可能被 Windows 或杀毒软件提示"未知发布者"，选择
     【更多信息】→【仍要运行】，或把程序加入杀毒软件白名单。
3. 程序会在同目录生成 pbxdialer.ini 保存你的设置，下次启动自动连接。

三、连接设置（界面最上方）
------------------------------------------------------------------------
  MQTT 地址   PBX 所在网络的 MQTT 服务器 IP，例如 192.168.1.10
  端口        默认 1883（若 PBX 后台改过，按实际填写）
  Token       设备序列号。在 PBX 管理后台 → MQTT 设置 里可以看到，
              默认就是设备序列号，必须与后台一致，否则收不到任何回应
  用户名/密码  如果 PBX 的 MQTT 配置了账号密码才需要填，一般留空

填好后点【连接】。连接成功时：
  - 右上角状态显示"已连接"
  - 日志出现：MQTT 已连接 / 已订阅 response / event 主题
  - 随后自动获取分机列表，日志出现：分机列表已刷新: 共 N 个分机
  - 主叫分机下拉框会自动填上 PBX 上**已注册**的分机（几百个也支持，上限 2000 个）
  - 日志会写"已注册 N 个 / 共 M 个（未注册的 K 个已隐藏）"，一眼看出哪些没上线
  - 上次用过的主叫分机会自动填回框里（即使它不在分机列表里，例如 3149）

电脑必须能访问该 IP 的 1883 端口（跨网段/防火墙请放行）。


四、拨号
------------------------------------------------------------------------
1. 主叫分机：从下拉框选择，或直接在框里手动输入分机号（例如 3149）。
   下拉框里的分机是从 PBX 实时读取的；程序会记住上一次用的主叫，
   下次启动自动填好。
   * 注意：主叫必须是 PBX 上真实存在的分机，否则 PBX 会拒绝拨号。
2. 被叫号码：输入要拨打的电话号码或分机号，支持数字、*、#、+、-、. 。
   被叫是一个下拉框（和主叫一样）：程序会把你拨过的号码记下来
   （最近 12 个，最近的在最上面），点右侧箭头就能选，选中即填入。
   为了安全，启动时被叫框不自动填内容，避免误拨。
3. 自动接通：勾选后，对方接起即自动接通（对应接口的 autoanswer=yes）；
   不勾选为普通呼叫。是否需要该功能取决于 PBX 的配置。
   这一项默认就是勾上的，并且会记在 ini 里（autoanswer=1），
   下次启动按上次的勾选状态恢复；在界面上改一下就会立即写回 ini。
4. 点【拨号】，或者直接按回车（见下面第 5 条）。日志会显示发出的
   JSON 和 PBX 的回应，例如：
      拨号命令已发送: 8001 → 8002
      → 已发送 {"cmd":"dial",...,"caller":"8001","callee":"8002"}
      响应: status=Success message=success  callid=...
   status=Success 表示 PBX 已受理。

5. 快捷键：
       被叫框里按【回车】        = 拨号
       主叫框里按【回车】        = 被叫框有号码就拨号，没号码就跳到被叫框
       下拉框里按【↓】           = 展开历史号码，选好后按【回车】拨号


五、挂机
------------------------------------------------------------------------
点【挂机】结束当前通话。日志显示：
      挂机命令已发送 (callid=...)
      响应: status=Success message=Channel Hungup
如果还没拨过号，会提示"没有可挂断的通话"。


六、界面说明
------------------------------------------------------------------------
  状态            未连接 / 连接中... / 已连接
  状态日志区      每一步的详细记录（时间 + 内容），出问题先看这里；
                  新内容会自动滚到最下面，永远看得到最新一条
  断开            断开 MQTT 连接（不影响已保存的设置）
  【刷新分机】    重新向 PBX 请求一次分机列表（不用断开重连）

  说明：为了界面干净，【诊断】和【复制日志】两个按钮默认不显示。
        它们只在现场排障时用得上（见第七节的 show_diag）。

  说明：主叫分机是一个可输入的下拉框。即使分机列表没读出来，
        也可以直接在里面手动输入分机号（例如 3149）后拨号。
  说明：被叫号码也是一个下拉框，点右侧箭头能看到最近拨过的号码，选中即填入。


七、现场微调（改 ini 就能试，不用重装软件）
------------------------------------------------------------------------
程序同目录的 pbxdialer.ini 除了 IP/Token，还支持下面这些"协议微调"项，
用记事本打开改完、重启软件即生效（%s 会被替换成 Token）：

  caller         上次使用的主叫分机（程序自动写，一般不用手改）
  callee_history 被叫号码历史，用 | 分隔，最近的在前，
                 例如 callee_history=8002|8003|13900001111
  autoanswer     拨号时是否自动接通：1=勾选（默认），0=不勾选。
                 等价于界面上的"自动接通"勾选框，改哪个都一样
  show_diag      是否显示【诊断】【复制日志】两个按钮：0=不显示（默认），
                 1=显示。平时保持 0 界面最干净；现场排障时改成 1，
                 重启软件就会多出这两个按钮
  only_registered 主叫下拉框是否只列"已注册"的分机：1=只列已注册（默认），
                 0=列出 PBX 上配置的全部分机。
                 PBX 返回的 status 为 Unavailable 的分机（没注册/掉线）会被隐藏，
                 Idle / InUse / Ringing / Busy 都算可用。
                 如果整份列表都被标成 Unavailable（固件不返回 status），
                 程序会自动退回"显示全部"并在日志里提示。
  topic_system   获取分机列表用的命令主题
                 默认 device/%s/api/v1.0/command/system
  topic_call     拨号/挂机用的命令主题
                 默认 device/%s/api/v1.0/command/call
  sub_extra      额外订阅的主题，多个用 ; 分隔（一般不用填，
                 程序已默认订阅 device/%s/#）
  dial_extra     拨号时追加的 JSON 片段，例如：
                 dial_extra="dialpermission":"3149"
                 （主叫不是真实分机时，PBX 要求用它指定外呼权限分机）
  test_topic     【诊断】按钮发送的主题（空=用 topic_system）
  test_payload   【诊断】按钮发送的内容（空=发 deviceinfo 请求）
                 （这两项只在 show_diag=1 时才有意义）
  cmd_qos        命令用 QoS1(默认,能看到服务器确认) 还是 QoS0

出问题时最常用的做法：
  1) 把 ini 里的 show_diag 改成 1，重启软件；
  2) 点【诊断】，看日志里有没有"响应:"；
  3) 点【复制日志】，把内容粘贴出来发给技术支持。
  （不打开 show_diag 也可以：直接看同目录的 pbxdialer_debug.log）


八、常见问题
------------------------------------------------------------------------
1) 一直显示"连接失败, 2 秒后重试"
   - 检查 IP、端口是否正确，电脑能否 ping 通；
   - 检查防火墙是否放行 1883 端口；
   - 若 PBX 的 MQTT 用了账号密码，请填写用户名/密码。

2) 连上了但一直没有"分机列表已刷新" / 拨号没有回应
   - 程序会在 12 秒后自动提示"未收到分机列表响应"或"未收到拨号响应"；
   - 99% 是 Token 不对。Token 必须与 PBX 后台 MQTT 设置中的完全一致；
   - 若仍不行：把程序同目录下的 pbxdialer_debug.log 发给技术支持。
     该文件记录了完整的收发报文（主题+内容），能直接定位问题；
   - 日志里若出现"订阅被服务器拒绝"，说明 MQTT 服务器限制了订阅权限，
     需要 PBX 管理员放开 device/<Token>/# 主题的订阅。

3) 拨号后 PBX 返回 status 不是 Success
   - 看日志里的 message 字段；
   - 主叫分机不是真实分机时，PBX 可能要求先配置 dialpermission。

4) 程序被拦截 / 打不开
   - 程序是未签名的绿色软件，加入杀毒软件白名单即可；
   - 若双击无反应，右键 → 以管理员身份运行试试。

5) 换电脑后设置丢了
   - 设置保存在 exe 同目录的 pbxdialer.ini，把它一起拷贝过去即可。


6) 分机有几百个，下拉框会不会显示不全
   - 程序会完整解析 PBX 返回的分机列表，最多显示 2000 个（几百个没
     问题）；真的超过时日志会提示"已达显示上限"；
   - 即使超限，直接在主叫框里输入分机号也照样能拨。

7) 主叫/被叫的记忆规则
   - 主叫：自动记住上次用的分机，下次启动直接填好；
   - 被叫：不自动填（防止误拨），但会进历史下拉框，最近 12 个，
     点右侧箭头就能选，选中即填入，再按回车就拨。


九、能配哪些 PBX（兼容性）
------------------------------------------------------------------------
这个程序不是通用 PBX 客户端，它说的是国威（Smart PBX Manager）那一套
MQTT 接口的"方言"。判断能不能用，看一条就够：

    PBX 管理后台里有没有「IPPBX API 接口 / MQTT 设置」，
    并且报文形如 {"cmd":"dial","caller":"8001","callee":"8002"}

  能用：
    - 国威 Smart PBX Manager 系列设备（NSN 等型号，只要固件带这套 API）
    - 国威给其他牌子做的 OEM/贴牌机（同一套固件，换个 logo）
    - 同一套 API 的不同固件版本：主题不一样时改 ini 的
      topic_system / topic_call 即可，不用重新编译

  不能用（接口完全不同，改 ini 解决不了）：
    - Asterisk / FreePBX / 迅时 / Yeastar  —— AMI 协议（TCP 5038）
    - 3CX —— REST/OData + OAuth
    - 华为 / 中兴 / Cisco —— 私有 CTI / TAPI
    - 普通 SIP 话机（它们本身不是 PBX）

  MQTT 传输层本身是通用的（标准 3.1.1），不通用的是上层的命令和字段名。
  详细对照和"要支持别的品牌该怎么改"见同目录的 兼容性说明.md。


十、目录里都有什么
------------------------------------------------------------------------
  拨号.exe              主程序（单文件，无需安装）
  使用说明.txt          本文件
  pbxdialer.ini         首次启动时自动生成，保存 IP/端口/Token/主叫/被叫历史等设置
                        （可删除，删除后下次启动不会自动连接）
  pbxdialer_debug.log   自动生成的收发报文记录，用于排查问题（可删除）


十一、技术说明（可选看）
------------------------------------------------------------------------
- 基于 MQTT 3.1.1 直连 PBX 的 MQTT 服务器，命令主题：
      device/<Token>/api/v1.0/command/call    拨号 / 挂机
      device/<Token>/api/v1.0/command/system  获取分机列表
  订阅主题（优先通配，被拒时自动改回精确主题）：
      device/<Token>/#                       通配（推荐）
      device/<Token>/api/v1.0/response       精确
      device/<Token>/api/v1.0/event          精确
- 命令以 QoS1 发送，可在 debug 日志里看到服务器的 PUBACK 确认。
- 不含任何第三方运行库，不联网上报数据，只连接你填写的 MQTT 服务器。
